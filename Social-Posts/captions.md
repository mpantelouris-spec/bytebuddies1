## Post 2 — Take it apart. Make it better. (post_2.png)

Engineers don't get it right first time. They swap, test and improve. 🔧

So we built that into ByteBuddies. Pupils click any part of their robot (the digger's scoop, the car's wheels, the dog's ears) and swap it or take it off.

🪣 Scoop → claw → drill
🛞 Wheels → tracks → hover pads

And it matters: put a car on hover pads and it really does start hovering in the game. Every change is a little experiment.

That's design technology and computing in one lesson.

## Post 3 — They build the track. Then they code the car. (post_3.png)

Most coding games give children a level. We give them the level editor. 🏁

In the ByteBuddies Track Maker, pupils:
🛣️ Snap together straights, hairpins and S-bends
🚧 Put bumpers, boost pads and ramps in any lane
🏎️ Choose how many rival karts to race, and how fast

Then they have to write the code to get round the track they designed. Make it too hard and they'll find out, fast. 😄

They can share their track with a code, so the whole class can race each other's designs.

## Post 4 — The kart kept crashing. Two lines fixed it. (post_4.png)

The best computing lessons start with something going wrong. 💥

The kart drives straight into the bumper. Again. And again.

Then a pupil adds this:

def on_object_ahead():
    robot.lane_clear()

Now the kart *sees* the bumper coming and changes lane by itself.

In two lines they've used:
✅ An event: when something happens, do this
✅ A sensor: the kart detects what's ahead
✅ Debugging: spot the problem, fix it, test again

Blocks or real Python, their choice.

## Post 5 — Every part has a trade-off. (post_5.png)

"Why is my robot so slow?" might be the best question a child can ask. 🤔

Every ByteBuddies robot has a stats card that changes as pupils build:
⚡ Speed
🛞 Grip
🏋️ Weight
🦾 Tools

More wheels, more grip. Bigger body, more weight, less speed. Add a scoop and Tools goes up.

The card even suggests what to try next. That's design → test → improve, the way real engineers work, and it happens before anyone writes a line of code.
